<p>This week's apps are small, and every one of them is something you might actually send to somebody. The one idea behind all of them fits in a sentence: <strong>an app can get information from three places - from you, from the person using it, and from the link that opened it.</strong></p>
<section id="random">
<h2>1. How an app picks at random</h2>
<p>The Magic 8-Ball and the Decision Maker both <em>pick</em>. Neither one thinks about it. Somewhere in the code there is a line that asks the browser for a random number, and that number decides which answer comes out.</p>
<p>That has three consequences worth knowing:</p>
<ul>
  <li><strong>The same answer can come up twice in a row.</strong> Or three times. That is not a bug - a coin can land heads twice. If it bothers you, you can ask the AI for <em>"never show the same answer twice in a row"</em>, and it will.</li>
  <li><strong>Every answer is equally likely</strong>, unless you ask otherwise. If you want the 8-Ball to say <em>yes</em> more often, put <em>yes</em> in the list more than once.</li>
  <li><strong>The app does not read your question.</strong> The box you type into on the Magic 8-Ball is there to make it feel real. Try asking it nothing at all.</li>
</ul>
<p class="aside">Computers are famously bad at being truly random, so what they actually produce is a number that <em>looks</em> random enough for any game, quiz or dinner decision you will ever build. For picking tacos, that is plenty.</p>
</section>
<section id="asking">
<h2>2. Asking for a change</h2>
<p>Every lab this week has an optional step called <em>Make it yours</em>, and it is the same move every time: you describe a change in plain words, and the AI makes it.</p>
<p>Three habits make that go well.</p>
<p><strong>One change at a time.</strong> <em>"Make the answer fade in"</em> is one change. <em>"Make the answer fade in, add a sound, change the colors and make it work on a phone"</em> is four, and when one of them goes wrong you will not know which.</p>
<p><strong>Say what it should look or feel like, not how to build it.</strong> You do not need to know the word for anything. <em>"Make the answer float up slowly, like it is rising through water"</em> works better than any technical term you could guess at.</p>
<p><strong>End with "keep everything else the same".</strong> Left to itself, an AI asked to change one thing will sometimes redesign three. That sentence is doing the dirty work, and you have been writing it since chapter 1.</p>
<div class="prompt">
  <button class="btn copy" data-copy="prompt-1">Copy prompt</button>
  <pre id="prompt-1">Make the answer fade in slowly, like it is floating up through dark water. Keep everything else exactly the same.</pre>
</div>
</section>
<section id="input">
<h2>3. Apps that listen</h2>
<p>The Magic 8-Ball's answers are <strong>yours</strong>. You typed them into the prompt, the AI put them in the code, and every person who ever uses it gets those same answers. That is <strong>content</strong>.</p>
<p>The Decision Maker is different. It has no options at all until somebody types them in. Those options come from the <strong>user</strong> - the person using the app, who might be you, or might be someone you sent it to. That is <strong>input</strong>.</p>
<p>Two things change the moment an app listens:</p>
<ul>
  <li><strong>You have to say what happens when someone uses it wrong.</strong> What if they press Decide with nothing in the list? A blank screen feels broken. A friendly <em>"Add at least two options first"</em> feels finished. The screen an app shows when there is nothing to show is called the <strong>empty state</strong>, and the AI forgets it unless you ask.</li>
  <li><strong>The input disappears when the page is refreshed.</strong> Everything someone typed lived inside the open page, and a refresh starts it again from nothing. Lab 4.5 fixes that for the Decision Maker. A whole later chapter is about the other ways.</li>
</ul>
</section>
<section id="feel">
<h2>4. Designing for a feeling</h2>
<p>Most apps are judged on whether they work. Breathing Buddy is judged on whether it feels <strong>calm</strong>. That is a design question, and it is the one job the AI cannot finish for you, because only a person can feel it.</p>
<p><strong>Color does most of the work.</strong> Soft, low-contrast colors read as calm; bright reds and yellows read as urgent. You do not have to pick them yourself. <a href="https://coolors.co">coolors.co</a> generates palettes - press the space bar until one feels right. Each color has a <strong>code</strong> like <code>#264653</code>: a <code>#</code> and six letters and numbers. Copy those codes into your prompt and the AI will use exactly those colors.</p>
<p><strong>Pace matters.</strong> A circle that eases smoothly from small to big feels like breathing. One that snaps from one size to the other feels like a warning light. If yours snaps, ask for it to <em>"grow and shrink smoothly"</em>.</p>
<p><strong>Move one thing.</strong> A calm screen has one thing moving on it. If the background is shifting, the words are pulsing and the circle is growing, nothing feels calm.</p>
<p><strong>Some people get sick from motion on a screen.</strong> Phones and computers have a setting called <em>reduce motion</em>, and a well-made app notices it. That is the Grow step in lab 4.3, and chapter 5 comes back to it properly.</p>
</section>
<section id="address">
<h2>5. Information in the address</h2>
<p>Look at this address:</p>
<p><code>https://you.github.io/vibe-coding/invite/?to=Sam&amp;event=Game%20Night</code></p>
<p>Everything up to the <code>?</code> is the page you already know how to find. <strong>Everything after the <code>?</code> is information for the page to read.</strong> It is called a <strong>query string</strong>, and each piece of it is a <strong>URL parameter</strong>:</p>
<ul>
  <li><code>?</code> - the start of the information. Only one per address.</li>
  <li><code>to=Sam</code> - a name and a value, joined by <code>=</code>.</li>
  <li><code>&amp;</code> - <em>and here is another one</em>.</li>
  <li><code>event=Game%20Night</code> - another name and value.</li>
</ul>
<p>The page reads those when it opens. So one page, <code>invite/index.html</code>, can be a hundred different invites. You never make a second page; you make a second link.</p>
<p><strong>Spaces are not allowed in an address</strong>, so browsers write them as <code>%20</code>. You can type an ordinary space in the address bar and the browser will swap it in for you. If <code>%20</code> shows up on the page itself, the AI forgot to turn it back into a space - tell it so.</p>
<p><strong>Capital letters count.</strong> <code>?To=Sam</code> and <code>?to=Sam</code> are different names, exactly like <code>Photo.JPG</code> and <code>photo.jpg</code> were in chapter 3.</p>
<p class="aside">You have been using query strings for years without seeing them. Search for something on almost any website and look at the address bar afterwards - your search is sitting right there after a <code>?</code>.</p>
</section>
<section id="in-the-link">
<h2>6. A link that saves - and who can see it</h2>
<p>If a link can carry a name, it can carry a whole list:</p>
<p><code>.../decision-maker/?options=Pizza,Tacos,Sushi</code></p>
<p>That is what lab 4.5 does. The Decision Maker writes its list into a link, so the list survives a refresh, a bookmark keeps it, and a text message shares it. No account, no storage, nothing to set up.</p>
<p><strong>The catch is that the list is printed right there in the address.</strong> Anybody who has the link can read it - whoever you sent it to, whoever they forward it to, and anyone who glances at your browser history. So a link is a fine place for <em>Pizza, Tacos, Sushi</em> and a terrible place for anything private. Names, phone numbers, grades, anything you would not write on a postcard: not in a link.</p>
<p><strong>Commas are the other catch.</strong> If the options are separated by commas, then an option with a comma in it - <em>Mac, and cheese</em> - comes out as two options. That is called a <strong>separator</strong> problem, and there is a Read it question about it in 4.5.</p>
</section>
<section id="looks">
<h2>7. Picking a look for your adventure</h2>
<p>A choose-your-own-adventure is the same underneath whatever it looks like: a list of scenes, each with some words and a few choices, each choice leading to another scene. The look is a costume on top. Pick one:</p>
<ul>
  <li><strong>Classic text adventure</strong> <em>(easiest)</em> - green text on black, like a computer from 1980. Choices as buttons, or typed commands like <em>go north</em>.</li>
  <li><strong>Storybook</strong> <em>(easy)</em> - one page per scene with a big picture made of emoji, and a page-turn between scenes.</li>
  <li><strong>Visual novel</strong> <em>(medium)</em> - a character's portrait standing over a background, their name above the text, and the text in a box at the bottom of the screen.</li>
  <li><strong>Telltale-style drama</strong> <em>(medium)</em> - comic-book scenes, dramatic dialogue, choices on a countdown timer, and the moment the screen says <em>"Sam will remember that."</em></li>
  <li><strong>Point-and-click escape room</strong> <em>(medium)</em> - a room with objects you click on, and each object leads somewhere.</li>
  <li><strong>Pixel-art retro</strong> <em>(medium)</em> - 8-bit scenes drawn in chunky pixels, like an old console game.</li>
  <li><strong>Blocky 3D world</strong> <em>(ambitious)</em> - each scene is a small world built from blocks, and the camera glides from place to place. It uses a library called <code>Three.js</code>, loaded from the internet like the QR library in chapter 1, so it needs a connection.</li>
</ul>
<p><strong>Borrow a look, never someone else's characters.</strong> <em>"A blocky world like Roblox"</em> describes a style, and that is fine. Asking for Roblox's own characters, a real game's logo, or Telltale's heroes is not yours to use - invent your own.</p>
<p><strong>Pictures of your own are welcome.</strong> A drawing, a photo, your dog as the hero: put the file beside the page and tell the AI its exact name, the same as the recipe card in chapter 2.</p>

<h2>8. When it breaks: describe it, don't fix it</h2>
<p>Something will stop working this week. When it does, the fastest route back is almost never guessing at a fix. It is <strong>describing what you see</strong>, precisely, and letting the AI work out why.</p>
<p><strong>Say the symptom, not your theory.</strong> <em>"When I press Enter in the box, the page goes blank and my list disappears"</em> is gold. <em>"I think the JavaScript is broken"</em> tells the AI nothing it can use.</p>
<p><strong>Ask it to look before it touches anything.</strong> This prompt stops the AI from rewriting half your app on a hunch:</p>
<div class="prompt">
  <button class="btn copy" data-copy="prompt-2">Copy prompt</button>
  <pre id="prompt-2">Without fixing any code, please identify what might be causing the issue and let me know.</pre>
</div>
<p>Read what it says. If it makes sense, tell it to go ahead and fix that one thing.</p>
<p><strong>Paste the exact error.</strong> If the Developer Console shows red text, copy all of it into the chat. The exact words matter far more than <em>"it broke"</em>.</p>
<p><strong>Sometimes it is you, and that is fine.</strong> If you pasted only half the file, or saved it with the wrong name, the AI does not know that - it will assume <em>its</em> code is wrong and start "fixing" something that was never broken. Before you ask, check the boring things: the whole file pasted, saved, the right name, refreshed.</p>

  <script>
    // Vibe Coding - lab handout behavior (SOURCE)
    //
    // This file is inlined into every published handout by build/build.py.
    // Edit it here, run the build, and every lab picks up the change.
    // Never edit the <script> block inside a file in publish/ - it is overwritten.
    //
    // Behavior only. The words on a handout are in its source in chapters/.
    // Jobs, in order:
    //   1. Light / dark mode, remembered
    //   2. Open and close the step cards
    //   3. Mark done buttons, remembered (optional steps never open by themselves)
    //   4. The progress bar (counts required steps only)
    //   5. Copy buttons
    //   6. Show / hide answers in Read it
    //   7. The lab report (only on handouts that have one): autosave, print to PDF
    //   8. Start over
    //
    // The page's <head> defines a LAB object (title, chapter, time, id) - the
    // generator writes it from the lab's source. Everything named below comes
    // from there.
    //
    // Privacy: everything saved lives in this browser's local storage on this
    // device. Nothing is sent anywhere.

    (function () {
      'use strict';

      // Names for what we save. Each lab has its own id so progress and report
      // drafts never bleed between labs. The theme is shared across handouts.
      const KEY_DONE   = LAB.id + '-done';
      const KEY_REPORT = LAB.id + '-report';
      const KEY_THEME  = 'vibe-theme';

      // Small helpers for saving and loading, wrapped so a browser with storage
      // turned off still gets a working page - it just won't remember.
      function load(key, fallback) {
        try { const v = localStorage.getItem(key); return v === null ? fallback : JSON.parse(v); }
        catch (e) { return fallback; }
      }
      function save(key, value) {
        try { localStorage.setItem(key, JSON.stringify(value)); } catch (e) { /* no storage; carry on */ }
      }

      const $ = (id) => document.getElementById(id);

      // Announce something to screen-reader users without showing it.
      const announcer = $('announce');
      function announce(message) {
        if (!announcer) return;
        announcer.textContent = '';
        setTimeout(function () { announcer.textContent = message; }, 50);
      }

      // Write the lab's name, chapter and time into the page.
      document.title = LAB.title + ' | Vibe Coding';
      if ($('lab-title'))  { $('lab-title').textContent = LAB.title; }
      if ($('lab-ribbon')) { $('lab-ribbon').textContent = LAB.chapter + '  ·  ' + LAB.time; }
      if ($('topbar-title')) { $('topbar-title').textContent = LAB.title; }


      // ---------------------------------------------------------------
      // 1. LIGHT / DARK MODE
      // The <head> already applied the saved choice before paint. This wires
      // up the button and keeps its label honest.
      // ---------------------------------------------------------------
      const themeButton = $('theme-toggle');
      if (themeButton) {
        const themeLabel = $('theme-label');
        const themeGlyph = $('theme-glyph');
        function renderTheme() {
          const dark = document.documentElement.getAttribute('data-theme') === 'dark';
          themeButton.setAttribute('aria-pressed', String(dark));
          themeLabel.textContent = dark ? 'Light mode' : 'Dark mode';   // names what it will switch TO
          themeGlyph.textContent = dark ? '☀' : '☾';
        }
        themeButton.addEventListener('click', function () {
          const dark = document.documentElement.getAttribute('data-theme') === 'dark';
          if (dark) { document.documentElement.removeAttribute('data-theme'); }
          else      { document.documentElement.setAttribute('data-theme', 'dark'); }
          try { localStorage.setItem(KEY_THEME, dark ? 'light' : 'dark'); } catch (e) {}
          renderTheme();
        });
        renderTheme();
      }


      // ---------------------------------------------------------------
      // 2. OPENING AND CLOSING CARDS
      // ---------------------------------------------------------------
      const steps = Array.from(document.querySelectorAll('.step'));

      // Some steps are OPTIONAL (the build marks them with class="optional").
      // Only the required ones count toward "done" - so a student who finishes
      // Picture it, Ask for it and Run it has finished the lab.
      const requiredSteps = steps.filter(function (s) { return !s.classList.contains('optional'); });
      const requiredNums  = requiredSteps.map(function (s) { return Number(s.dataset.step); });
      const hasOptional   = requiredSteps.length < steps.length;
      const TOTAL = requiredSteps.length;   // read from the page rather than assumed

      // Is this step one of the optional ones?
      function isOptional(step) { return step.classList.contains('optional'); }

      function openStep(step) {
        step.querySelector('.step-toggle').setAttribute('aria-expanded', 'true');
        step.querySelector('.step-body').hidden = false;
      }
      function closeStep(step) {
        step.querySelector('.step-toggle').setAttribute('aria-expanded', 'false');
        step.querySelector('.step-body').hidden = true;
      }

      steps.forEach(function (step) {
        step.querySelector('.step-toggle').addEventListener('click', function () {
          const isOpen = this.getAttribute('aria-expanded') === 'true';
          if (isOpen) { closeStep(step); } else { openStep(step); }
        });
      });


      // ---------------------------------------------------------------
      // 3. MARK DONE, REMEMBERED
      // ---------------------------------------------------------------
      let done = load(KEY_DONE, []);      // e.g. [1, 2, 3]

      function renderStep(step) {
        const num = Number(step.dataset.step);
        const isDone = done.includes(num);
        const button = step.querySelector('.mark');
        step.classList.toggle('done', isDone);
        button.setAttribute('aria-pressed', String(isDone));
        button.textContent = isDone ? 'Done ✓' : 'Mark done';
      }

      // Marking a step done closes it and opens the next unfinished one, and
      // moves keyboard focus there, so the page carries the student forward.
      steps.forEach(function (step) {
        step.querySelector('.mark').addEventListener('click', function () {
          const num = Number(step.dataset.step);
          if (done.includes(num)) {
            done = done.filter(function (n) { return n !== num; });
            renderStep(step);
          } else {
            done.push(num);
            renderStep(step);
            closeStep(step);

            // Which step comes next? Stay in the same kind of step:
            //  - after a required step, the next unfinished REQUIRED step. The
            //    optional ones never open by themselves - that is the point.
            //  - after an optional step, the next unfinished optional step below it.
            let next;
            if (isOptional(step)) {
              next = steps.find(function (s) {
                return isOptional(s) && Number(s.dataset.step) > num && !done.includes(Number(s.dataset.step));
              });
            } else {
              next = requiredSteps.find(function (s) { return !done.includes(Number(s.dataset.step)); });
            }

            // Move keyboard focus to the next step WITHOUT scrolling. A plain
            // focus() inside an LMS iframe makes iOS scroll the outer page to
            // the frame's top; the next step's header is already where the
            // collapsed one was, so no scrolling is wanted anyway.
            if (next) {
              openStep(next);
              next.querySelector('.step-toggle').focus({ preventScroll: true });
            } else if (!isOptional(step) && hasOptional) {
              // That was the last required step. Say so, and put focus on the
              // "Optional: go further" heading, which sits right below.
              announce('All required steps done. The rest are optional.');
              const optionalTitle = $('optional-title');
              if (optionalTitle) { optionalTitle.focus({ preventScroll: true }); }
            }
          }
          save(KEY_DONE, done);
          renderProgress();
        });
      });


      // ---------------------------------------------------------------
      // 4. THE PROGRESS BAR
      // ---------------------------------------------------------------
      const progressEl    = $('progress');
      const progressLabel = $('progress-label');
      const segments      = Array.from(document.querySelectorAll('.progress-bar span'));

      function renderProgress() {
        if (!progressEl) return;
        // Count required steps only. Optional ones are counted separately, as a bonus.
        const count = done.filter(function (n) { return requiredNums.includes(n); }).length;
        const extras = steps.filter(function (s) {
          return isOptional(s) && done.includes(Number(s.dataset.step));
        }).length;
        // On a lab with optional steps the label says "required", so nobody
        // wonders why the bar is full when there are still steps below it.
        const word = hasOptional ? 'required steps' : 'steps';
        segments.forEach(function (seg, i) { seg.classList.toggle('filled', i < count); });
        progressEl.setAttribute('aria-valuenow', String(count));
        if (count === TOTAL) {
          progressLabel.textContent = 'All ' + TOTAL + ' ' + word + ' done - nice work'
            + (extras > 0 ? ' (plus ' + extras + ' optional)' : '');
        } else {
          progressLabel.textContent = count + ' of ' + TOTAL + ' ' + word + ' done';
        }
      }


      // ---------------------------------------------------------------
      // 5. COPY BUTTONS
      // Each button names the <pre> it copies in data-copy.
  // ---------------------------------------------------------------
  document.querySelectorAll('.copy').forEach(function (button) {
    button.addEventListener('click', function () {
      const pre = $(button.dataset.copy);
      if (!pre) return;
      const text = pre.textContent;
      const originalLabel = button.textContent;

      function copied() {
        button.textContent = 'Copied ✓';
        announce('Copied to clipboard');
        setTimeout(function () { button.textContent = originalLabel; }, 1800);
      }
      // If the clipboard isn't available, select the text so Ctrl+C works.
      function fallback() {
        const range = document.createRange();
        range.selectNodeContents(pre);
        const sel = window.getSelection();
        sel.removeAllRanges(); sel.addRange(range);
        button.textContent = 'Press Ctrl+C';
        announce('Text selected. Press Control C to copy.');
        setTimeout(function () { button.textContent = originalLabel; }, 3000);
      }

      if (navigator.clipboard && navigator.clipboard.writeText) {
        navigator.clipboard.writeText(text).then(copied, fallback);
      } else { fallback(); }
    });
  });


  // ---------------------------------------------------------------
  // 6. SHOW / HIDE ANSWERS
  // ---------------------------------------------------------------
  document.querySelectorAll('.reveal').forEach(function (button) {
    button.addEventListener('click', function () {
      const answer = $(button.getAttribute('aria-controls'));
      const isOpen = button.getAttribute('aria-expanded') === 'true';
      answer.hidden = isOpen;
      button.setAttribute('aria-expanded', String(!isOpen));
      button.textContent = isOpen ? 'Show answer' : 'Hide answer';
    });
  });


  // ---------------------------------------------------------------
  // 7. THE LAB REPORT (only on handouts that have one - the chapter anchor)
  // ---------------------------------------------------------------
  const reportPanel = $('report');
  if (reportPanel) {
    // The questions are read from the page, so the source decides them.
    const questionFields = Array.from(reportPanel.querySelectorAll('textarea'));
    const REPORT_FIELDS = questionFields.map(function (ta) {
      const label = reportPanel.querySelector('label[for="' + ta.id + '"]');
      return { id: ta.id, label: label ? label.textContent.replace(/\s+/g, ' ').trim() : ta.id };
    });
    const nameInput = $('r-name');
    const urlInput  = $('r-url');           // may not exist before the publishing chapter
    const savedNote = $('report-saved');
    const allInputs = [nameInput, urlInput].filter(Boolean).concat(questionFields);

    // Put a saved draft back into the form on load.
    const draft = load(KEY_REPORT, {});
    allInputs.forEach(function (el) { if (draft[el.id]) { el.value = draft[el.id]; } });

    // Save the whole form whenever anything changes, once per pause in typing.
    let saveTimer = null;
    allInputs.forEach(function (el) {
      el.addEventListener('input', function () {
        clearTimeout(saveTimer);
        saveTimer = setTimeout(function () {
          const data = {};
          allInputs.forEach(function (i) { data[i.id] = i.value; });
          save(KEY_REPORT, data);
          if (savedNote) { savedNote.textContent = 'Saved on this device'; setTimeout(function () { savedNote.textContent = ''; }, 2000); }
        }, 400);
      });
    });

    // Make text safe to drop into HTML. The student's answers are their own
    // words; this makes sure a stray < or & can't change the page.
    function escapeHtml(text) {
      return String(text).replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;').replace(/"/g, '&quot;');
    }

    // Build the printable report from the form, then open the print dialog.
    // "Save as PDF" in that dialog is the PDF generator - no library, and
    // links stay clickable in the PDF.
    $('report-print-btn').addEventListener('click', function () {

      const url  = urlInput ? urlInput.value.trim() : '';
      const when = new Date().toLocaleDateString(undefined, { year: 'numeric', month: 'long', day: 'numeric' });

      // Only real web links become links in the PDF; anything else prints as text.
      const urlIsLink = /^https?:\/\/[^\s]+$/i.test(url);
      const urlLine = !urlInput ? ''
        : 'Link to the lab: ' + (!url ? '<em>not on the web yet</em>' : urlIsLink ? '<a href="' + escapeHtml(url) + '">' + escapeHtml(url) + '</a>' : escapeHtml(url)) + '<br>';

      let html = '';
      html += '<h1>Lab report - ' + escapeHtml(LAB.title) + '</h1>';
      html += '<p class="meta">Chapter: ' + escapeHtml(LAB.chapter) + '<br>';
      html += 'Student: <strong>' + escapeHtml(name) + '</strong><br>';
      html += urlLine;
      html += 'Report generated: ' + escapeHtml(when) + '</p>';

      REPORT_FIELDS.forEach(function (f, i) {
        const answer = $(f.id).value.trim();
        html += '<div class="qa">';
        html += '<p class="question">' + (i + 1) + '. ' + escapeHtml(f.label) + '</p>';
        html += '<p class="response">' + (answer ? escapeHtml(answer) : '<em>(no answer)</em>') + '</p>';
        html += '</div>';
      });

      html += '<h2>Steps marked done</h2><ul class="steps">';
      steps.forEach(function (s) {
        const n = Number(s.dataset.step);
        // The title without its "Optional" tag; the tag is added back in words.
        const titleEl = s.querySelector('.step-title') || s.querySelector('h2');
        const title = titleEl.textContent.trim() + (isOptional(s) ? ' (optional)' : '');
        html += '<li>' + (done.includes(n) ? '✓ ' : '☐ ') + escapeHtml(title) + '</li>';
      });
      html += '</ul>';
      html += '<p class="footer">Vibe Coding - CSC 145 - Finger Lakes Community College. Generated from the lab handout; the handout itself is one HTML file.</p>';

      $('report-print').innerHTML = html;
      document.body.classList.add('print-report');
      window.addEventListener('afterprint', function restore() {
        document.body.classList.remove('print-report');
        window.removeEventListener('afterprint', restore);
      });
      window.print();
    });

    // Clear the report draft: two clicks, no blocking dialog.
    const clearButton = $('report-clear');
    let clearArmed = false;
    clearButton.addEventListener('click', function () {
      if (!clearArmed) {
        clearArmed = true;
        clearButton.textContent = 'Really clear? Click again';
        setTimeout(function () { clearArmed = false; clearButton.textContent = 'Clear answers'; }, 4000);
        return;
      }
      allInputs.forEach(function (el) { el.value = ''; });
      save(KEY_REPORT, {});
      clearArmed = false;
      clearButton.textContent = 'Clear answers';
      announce('Report answers cleared');
    });
  }


  // ---------------------------------------------------------------
  // 8. START OVER (steps only - the report has its own clear button)
  // ---------------------------------------------------------------
  const resetButton = $('reset');
  if (resetButton) {
    resetButton.addEventListener('click', function () {
      done = [];
      save(KEY_DONE, done);
      steps.forEach(function (step, i) { renderStep(step); if (i === 0) { openStep(step); } else { closeStep(step); } });
      renderProgress();
      announce('Progress cleared. Starting from step one.');
      steps[0].querySelector('.step-toggle').focus({ preventScroll: true });
    });
  }


  // ---------------------------------------------------------------
  // 9. INSIDE AN LMS FRAME? REPORT OUR HEIGHT
  // When this page is embedded in an iframe (Brightspace, usually), the
  // parent page cannot see how tall we are. We tell it, so it can size the
  // frame to fit and avoid a second scrollbar. Only a number is sent - never
  // anything about the student - and only when the height actually changes,
  // so scrolling on a phone (where the address bar comes and goes) does not
  // cause a storm of messages. The parent decides whether to act on it.
  // ---------------------------------------------------------------
  if (window.parent !== window && 'ResizeObserver' in window) {
    let lastHeight = 0;
    const reportHeight = function () {
      const height = document.documentElement.scrollHeight;
      if (Math.abs(height - lastHeight) < 4) return;    // ignore sub-pixel wobble
      lastHeight = height;
      window.parent.postMessage({ vibeHeight: height }, '*');
    };
    new ResizeObserver(reportHeight).observe(document.body);
    window.addEventListener('load', reportHeight);
  }


  // ---------------------------------------------------------------
  // 10. THE HAND-IN LINK COMES FROM THE LMS
  // The "Click here to submit your work" card is hidden until it has a link.
  // The assignment URL belongs to the course running this page, not to the
  // page itself, so the Brightspace embed posts it in:
  //     frame.contentWindow.postMessage({ vibeSubmit: url }, 'https://our-site');
  // We accept it only from our own parent window, and only if it is an
  // https address. Anything else is ignored and the card stays hidden.
  // ---------------------------------------------------------------
  const submitCard = $('submit-card');
  function showSubmit(url) {
    if (typeof url !== 'string' || !/^https:\/\//i.test(url)) return;   // https only
    submitCard.href = url;
    submitCard.hidden = false;
  }
  if (submitCard) {
    // Route 1: the parent page posts the link in (the normal, LMS-embed route).
    if (window.parent !== window) {
      window.addEventListener('message', function (e) {
        if (e.source !== window.parent) return;
        showSubmit(e.data && e.data.vibeSubmit);
      });
    }
    // Route 2: the link is in the page's own address, ?submit=ENCODED-URL.
    // For a topic that cannot run script. The value must be URL-encoded
    // (encodeURIComponent), since LMS links are full of ? and & themselves.
    try {
      showSubmit(new URL(window.location.href).searchParams.get('submit'));
    } catch (e) { /* no usable address - card stays hidden */ }
  }


  // ---------------------------------------------------------------
  // FIRST DRAW
  // Draw every step from saved state, then open the first unfinished
  // REQUIRED one so a returning student lands where they left off. If every
  // required step is done, nothing opens: the lab is finished, and the
  // optional steps wait, closed, until the student chooses one.
  // ---------------------------------------------------------------
  steps.forEach(renderStep);
  renderProgress();
  const firstOpen = requiredSteps.find(function (s) { return !done.includes(Number(s.dataset.step)); });
  steps.forEach(function (s) { if (s === firstOpen) { openStep(s); } else { closeStep(s); } });
})();

    /* ====================================================================
       Vibe Coding - vocabulary pop-ups
       Inlined by the build into every lab and reading, after lab.js.

       The build also inlines a VOCAB object (from shared/vocabulary.html):

         VOCAB = {
           "tag": { title: "Tag", match: ["tag", "tags"], html: "<p>...</p>" },
           ...
         }

       What this script does:
         1. Walks the text of the page and, the FIRST time a vocabulary term
            appears in each step (or each section, on a reading), wraps that
            word in a small button. Later mentions in the same step are left
            alone, so a page is not covered in links.
         2. Clicking the button opens a small pop-up (a native <dialog>) with
            the term's definition and a link to the full vocabulary page.

       It never touches code samples in <pre>, the demo <textarea>s, links,
   other buttons, headings, or the pretend-browser chrome. Inline <code>
   IS allowed when the whole code element is the term - that is where
   "<title>" appears in a sentence - but not inside a longer code sample.
   ==================================================================== */
(function () {
  'use strict';
  if (typeof VOCAB !== 'object' || !VOCAB) return;
  const dialog = document.getElementById('vocab-dialog');
  if (!dialog) return;

  // ---------------------------------------------------------------
  // 1. ONE REGULAR EXPRESSION FOR EVERY SPELLING OF EVERY TERM
  // Longest spellings first, so "opening tag" wins over "tag".
  // ---------------------------------------------------------------
  const spellings = [];             // [{ text, id }]
  Object.keys(VOCAB).forEach(function (id) {
    (VOCAB[id].match || []).forEach(function (text) {
      if (text.trim()) spellings.push({ text: text.trim(), id: id });
    });
  });
  spellings.sort(function (a, b) { return b.text.length - a.text.length; });
  const byLower = {};
  spellings.forEach(function (s) { byLower[s.text.toLowerCase()] = s.id; });

  function escapeRegex(text) { return text.replace(/[.*+?^${}()|[\]\\]/g, '\\$&'); }
  const pattern = new RegExp(spellings.map(function (s) { return escapeRegex(s.text); }).join('|'), 'gi');

  // A match only counts if it is a whole word: no letter or digit directly
  // before it (when it starts with one) or after it (when it ends with one).
  // "tag" must not light up inside "tags" or "stage".
  // Dots, hyphens, slashes and underscores count as glue too, so "html" does
  // not light up inside the file name "qr-code.html".
  const GLUE = /[\w.\-\/_]/;
  function isWholeWord(text, start, end) {
    const first = text[start], last = text[end - 1];
    const before = text[start - 1] || ' ', after = text[end] || ' ';
    if (/\w/.test(first) && GLUE.test(before)) return false;
    if (/\w/.test(last) && GLUE.test(after)) return false;
    return true;
  }

  // ---------------------------------------------------------------
  // 2. WHERE NOT TO LOOK
  // ---------------------------------------------------------------
  const SKIP = 'pre, textarea, svg, a, button, label, input, select, script, style, h1, h2, dialog, .fake-chrome, .contents, .ribbon, .term-link, .tools-note, .submit-card';

  function skippable(node) {
    for (let el = node.parentElement; el; el = el.parentElement) {
      if (el.matches(SKIP)) return true;
    }
    return false;
  }

  // ---------------------------------------------------------------
  // 3. LINK THE FIRST MENTION OF EACH TERM IN EACH BLOCK
  // A "block" is a step body on a lab, or a section on a reading.
  // ---------------------------------------------------------------
  const main = document.getElementById('main');
  if (!main) return;
  let blocks = Array.from(main.querySelectorAll('.step-body, :scope > section'));
  if (!blocks.length) blocks = [main];

  blocks.forEach(function (block) {
    const seen = new Set();
    const walker = document.createTreeWalker(block, NodeFilter.SHOW_TEXT);
    const textNodes = [];
    let node;
    while ((node = walker.nextNode())) {
      if (node.nodeValue.trim() && !skippable(node)) textNodes.push(node);
    }
    textNodes.forEach(function (textNode) { linkTerms(textNode, seen); });
  });

  function linkTerms(textNode, seen) {
    const text = textNode.nodeValue;

    // Inside inline <code>, link ONLY when the whole code element is the term:
    // <code>&lt;title&gt;</code> in a sentence is a mention and should link, but
    // a code sample like <code>&lt;p&gt;Some &lt;strong&gt;bold&lt;/strong&gt; words&lt;/p&gt;</code>
    // is an example, not a mention, and should stay plain.
    const codeEl = textNode.parentElement && textNode.parentElement.closest('code');
    const codeWhole = codeEl ? codeEl.textContent.trim() : null;

    pattern.lastIndex = 0;
    let match, last = 0;
    const pieces = [];
    while ((match = pattern.exec(text))) {
      const start = match.index, end = start + match[0].length;
      const id = byLower[match[0].toLowerCase()];
      if (!id || seen.has(id) || !isWholeWord(text, start, end)) continue;
      if (codeEl && match[0] !== codeWhole) continue;      // a code sample, not a mention
      seen.add(id);
      pieces.push(document.createTextNode(text.slice(last, start)));
      const button = document.createElement('button');
      button.type = 'button';
      button.className = 'term-link';
      button.dataset.term = id;
      button.textContent = match[0];
      button.setAttribute('aria-label', match[0] + ' - show definition');
      pieces.push(button);
      last = end;
    }
    if (!pieces.length) return;
    pieces.push(document.createTextNode(text.slice(last)));
    const parent = textNode.parentNode;
    pieces.forEach(function (piece) { parent.insertBefore(piece, textNode); });
    parent.removeChild(textNode);
  }

  // ---------------------------------------------------------------
  // 4. THE POP-UP
  // A native <dialog>: Escape closes it, focus stays inside it, and the
  // page behind is dimmed. When it closes, focus goes back to the word
  // that opened it.
  // ---------------------------------------------------------------
  const titleEl = dialog.querySelector('#vocab-title');
  const bodyEl  = dialog.querySelector('#vocab-body');
  const moreEl  = dialog.querySelector('#vocab-more');
  let opener = null;

  function open(id, button) {
    const entry = VOCAB[id];
    if (!entry) return;
    opener = button;
    titleEl.innerHTML = entry.title;
    // The definition HTML comes from shared/vocabulary.html, written by the
    // course author and inlined at build time - not from anything a visitor
    // typed - so putting it in with innerHTML is safe here.
    bodyEl.innerHTML = entry.html;
    if (moreEl) moreEl.hash = '#' + id;
    if (typeof dialog.showModal === 'function') { dialog.showModal(); } else { dialog.setAttribute('open', ''); }
  }

  document.addEventListener('click', function (e) {
    const button = e.target.closest('.term-link');
    if (button) { e.preventDefault(); open(button.dataset.term, button); }
  });

  dialog.querySelector('#vocab-close').addEventListener('click', function () { dialog.close(); });
  // Clicking the dimmed backdrop (outside the pop-up's box) closes it too.
  dialog.addEventListener('click', function (e) {
    const box = dialog.getBoundingClientRect();
    const outside = e.clientX < box.left || e.clientX > box.right || e.clientY < box.top || e.clientY > box.bottom;
    if (outside) dialog.close();
  });
  dialog.addEventListener('close', function () { if (opener) { opener.focus(); opener = null; } });
})();
  </script>
  <script>
    /* ====================================================================
       Vibe Coding - reading pages - the live demos
       Inlined by the build into every reading page, after lab.js (which
       handles the theme toggle, copy buttons, and show/hide answers).

       A demo is a block like this in the reading's source:

         <div class="demo" data-file="hello.html">
           <textarea>...starting code...</textarea>
         </div>

       This script turns each one into a two-pane widget: the code on the left,
       editable, and on the right a pretend browser window - a tab that shows
       the page's <title>, an address bar that shows the file name, and the
       page itself rendered live in a sandboxed frame. Edit the code and the
       render updates as you type. A Reset button puts the starting code back.

       A demo with data-squish="yes" also gets two buttons, Squish and Spread
       out, that rewrite the code with all its spacing removed or restored.
       The render never changes - that is the whole point of that demo.
       ==================================================================== */
    (function () {
      'use strict';

      // Turn every .demo block on the page into a live widget.
      document.querySelectorAll('.demo').forEach(buildDemo);

      function buildDemo(demo, index) {
        const textarea = demo.querySelector('textarea');
        if (!textarea) return;

        const fileName = demo.dataset.file || 'index.html';
        const original = textarea.value;              // kept for Reset and Spread out
        const id = 'demo-' + (index + 1);

        // ---- Build the widget's HTML around the existing textarea ----
        // Labels and ids are unique per demo so screen readers can tell them apart.
        textarea.id = id + '-code';
        // Tall enough to show the whole starting code without scrolling (up to a limit).
        textarea.rows = Math.min(original.split('\n').length + 1, 26);
        textarea.setAttribute('spellcheck', 'false');
        textarea.setAttribute('autocapitalize', 'off');
        textarea.setAttribute('autocomplete', 'off');

        const codePane = document.createElement('div');
        codePane.className = 'demo-code';
        codePane.innerHTML =
          '<div class="demo-bar">' +
          '  <label for="' + id + '-code">Code <span class="demo-hint">- edit me</span></label>' +
          '  <span class="demo-buttons">' +
          (demo.dataset.squish === 'yes'
            ? '<button type="button" class="btn quiet demo-squish">Squish</button>' +
              '<button type="button" class="btn quiet demo-spread">Spread out</button>'
            : '') +
          '  <button type="button" class="btn quiet demo-reset">Reset</button>' +
          '  </span>' +
          '</div>';
        codePane.appendChild(textarea);

        // The pretend browser. Everything here is decoration except the iframe,
        // which really does render the code.
        const browser = document.createElement('div');
        browser.className = 'demo-browser';
        browser.innerHTML =
          '<div class="fake-chrome" aria-hidden="true">' +
          '  <div class="fake-tabs">' +
          '    <span class="fake-dots"><i></i><i></i><i></i></span>' +
          '    <span class="fake-tab"><span class="fake-favicon"></span><span class="fake-title"></span></span>' +
          '  </div>' +
          '  <div class="fake-address"><span class="fake-nav">‹ › ↻</span><span class="fake-url"></span></div>' +
          '</div>' +
          '<iframe class="demo-frame" title="Rendered page for this demo" sandbox="allow-scripts"></iframe>';

        demo.innerHTML = '';
        demo.append(codePane, browser);

        const frame    = browser.querySelector('.demo-frame');
        const tabTitle = browser.querySelector('.fake-title');
        const urlBox   = browser.querySelector('.fake-url');
        urlBox.textContent = 'file:///Desktop/vibe-coding/' + fileName;

        // ---- Rendering ----
        // The tab shows whatever is between <title> and </title>. When a page has
        // no title, real browsers show the file name instead - so do we. That is
        // a small lesson in itself: the tab is never blank, it just falls back.
        function render() {
          const code = textarea.value;
          frame.srcdoc = code;
          const match = code.match(/<title>([\s\S]*?)<\/title>/i);
          const title = match ? match[1].replace(/\s+/g, ' ').trim() : '';
          tabTitle.textContent = title || fileName;
        }

        // Re-render a moment after the student stops typing, not on every key,
        // so a slow machine does not stutter.
        let timer = null;
        textarea.addEventListener('input', function () {
          clearTimeout(timer);
          timer = setTimeout(render, 150);
        });

        // Tab key inside the code box inserts two spaces instead of moving focus,
        // which is what a code editor does. Escape then Tab still moves focus, so
        // keyboard users are never trapped - and we say so in the label's title.
        let escaped = false;
        textarea.title = 'Tab inserts spaces here. Press Escape, then Tab, to move on.';
        textarea.addEventListener('keydown', function (e) {
          if (e.key === 'Escape') { escaped = true; return; }
          if (e.key === 'Tab' && !escaped) {
            e.preventDefault();
            const start = textarea.selectionStart, end = textarea.selectionEnd;
            textarea.setRangeText('  ', start, end, 'end');
            textarea.dispatchEvent(new Event('input'));
          }
          escaped = false;
        });

        // ---- Buttons ----
        codePane.querySelector('.demo-reset').addEventListener('click', function () {
          textarea.value = original;
          render();
          textarea.focus();
        });

        const squish = codePane.querySelector('.demo-squish');
        if (squish) {
          // Squish: every run of spaces, tabs and newlines becomes one space.
          // The browser treats them the same, so the render does not change.
          squish.addEventListener('click', function () {
            textarea.value = textarea.value.replace(/\s+/g, ' ').trim();
            render();
          });
          // Spread out: back to the nicely indented original.
          codePane.querySelector('.demo-spread').addEventListener('click', function () {
            textarea.value = original;
            render();
          });
        }

        render();
      }
    })();
  </script>
