<section id="text-file">
<h2>1. A web page is a text file</h2>
<p>When you double-clicked <code>qr-code.html</code> and your browser opened it, here is what happened: the browser read the file from top to bottom, like you’d read a recipe, and drew what it described. That’s all a web page is. A text file with a description of a page in it, and a browser that knows how to read the description.</p>
<p>The file has two kinds of things in it. <strong>Words you’ll see</strong> on the page - the heading, the paragraphs, the label on a button. And <strong>instructions about those words</strong> - <em>this is a heading, this is a paragraph, this is a link to somewhere.</em> The instructions are called <strong>tags</strong>, and they’re the only thing that makes it a web page instead of a plain note.</p>
<p>Here is the smallest one that does anything. Change the words and watch.</p>

<div class="demo" data-file="first.html">
<textarea>&lt;!DOCTYPE html&gt;
&lt;html&gt;
  &lt;body&gt;
    &lt;h1&gt;Hello, world&lt;/h1&gt;
    &lt;p&gt;This is a web page. Change me.&lt;/p&gt;
  &lt;/body&gt;
&lt;/html&gt;</textarea>
</div>

<p>Notice the tab at the top of the pretend browser says <code>first.html</code>. That’s the file name. In a moment you’ll learn how to make the tab say something better.</p>
</section>

<section id="tags">
<h2>2. Tags: the angle brackets</h2>
<p>A tag is a word in angle brackets: <code>&lt;h1&gt;</code>. Most tags come in pairs, like <strong>bookends</strong>: an <strong>opening tag</strong> that says <em>start being a heading</em>, and a <strong>closing tag</strong> that says <em>stop</em>. The closing tag is the same word with a slash in front: <code>&lt;/h1&gt;</code>. Whatever sits between the bookends is the <strong>content</strong>, and the tags tell the browser what the content <em>is</em>.</p>

<figure class="diagram">
  <svg viewBox="0 0 640 170" role="img" aria-labelledby="tag-anatomy-title tag-anatomy-desc">
    <title id="tag-anatomy-title">The anatomy of a tag</title>
    <desc id="tag-anatomy-desc">The line h1 Hello, world h1 shown in three parts: the opening tag h1 in angle brackets, labeled "start being a heading"; the words Hello, world, labeled "the content, what shows on the page"; and the closing tag slash h1 in angle brackets, labeled "stop - the slash means end".</desc>
    <defs><marker id="arrowhead" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7" markerHeight="7" orient="auto"><path class="arrowhead" d="M0,0 L10,5 L0,10 z"/></marker></defs>
    <rect class="box-soft" x="60" y="60" width="90" height="46" rx="8"/>
    <rect class="box" x="170" y="60" width="180" height="46" rx="8"/>
    <rect class="box-soft" x="370" y="60" width="110" height="46" rx="8"/>
    <text class="label-strong" x="105" y="90" text-anchor="middle">&lt;h1&gt;</text>
    <text class="label" x="260" y="90" text-anchor="middle" style="font-size:18px">Hello, world</text>
    <text class="label-strong" x="425" y="90" text-anchor="middle">&lt;/h1&gt;</text>
    <path class="arrow" d="M105,58 L105,38"/>

<p>Tags nest inside each other like boxes - or like bookends on a shelf that has smaller bookends on it. A paragraph can sit inside the body; a bit of bold can sit inside a paragraph. The rule is simple: whatever you open last, you close first. <code>&lt;p&gt;Some &lt;strong&gt;bold&lt;/strong&gt; words&lt;/p&gt;</code> - the <code>strong</code> bookends sit inside the <code>p</code> bookends.</p>
<p>Try this in the demo below: <strong>delete the <code>&lt;/h1&gt;</code></strong> - take away the right-hand bookend - and see what happens to the rest of the page. Then press Reset. That’s the most common mistake in all of HTML, and now you know what it looks like.</p>

<div class="demo" data-file="tags.html">
<textarea>&lt;!DOCTYPE html&gt;
&lt;html&gt;
  &lt;body&gt;
    &lt;h1&gt;A heading&lt;/h1&gt;
    &lt;p&gt;A paragraph with &lt;strong&gt;a few bold words&lt;/strong&gt; in it.&lt;/p&gt;
    &lt;p&gt;Another paragraph, with &lt;em&gt;emphasis&lt;/em&gt; this time.&lt;/p&gt;
  &lt;/body&gt;
&lt;/html&gt;</textarea>
</div>
</section>

<h3>All six, live</h3>
<p>This page has every landmark. Three things to try, in order:</p>
<ol>
  <li><strong>Change the words inside <code>&lt;title&gt;</code></strong> and watch the browser tab, not the page. This is the one thing in the head you’ll change most often.</li>
  <li><strong>Change <code>purple</code> to another color</strong> inside <code>&lt;style&gt;</code>. Try <code>tomato</code>, <code>steelblue</code>, <code>goldenrod</code>.</li>
  <li><strong>Change the message</strong> inside the quotes in <code>&lt;script&gt;</code>. That text appears when you click the button - it comes from the script, not from the body.</li>
</ol>

<div class="demo" data-file="six.html">

<p class="aside"><strong>Head or body?</strong> If it’s something a visitor <em>sees</em>, it’s in the body. If it’s a setting - the tab’s name, the colors - it’s in the head. That one question answers most “where do I look?” moments for the rest of the semester.</p>

<section id="paragraphs">
<h2>4. Paragraphs: <code>&lt;p&gt;</code></h2>
<p>Words on a page go in paragraphs, and a paragraph is a <code>&lt;p&gt;</code> tag with words inside. The browser puts a little space above and below each one, so two paragraphs look like two paragraphs. Every paragraph gets its own pair of tags.</p>
<p>Try adding a third paragraph below the second. Then try <strong>deleting all four <code>p</code> tags</strong> and see what the browser does with the words when nobody tells it what they are.</p>

<div class="demo" data-file="paragraphs.html">
<textarea>&lt;!DOCTYPE html&gt;
&lt;html&gt;
  &lt;body&gt;
    &lt;p&gt;This is the first paragraph. It has a couple of sentences in it, so you can see how it wraps.&lt;/p&gt;
    &lt;p&gt;This is the second. Notice the space between them - the browser added that because they are paragraphs.&lt;/p&gt;
  &lt;/body&gt;
&lt;/html&gt;</textarea>
</div>

<p>Without the tags the words run together into one lump, because the browser has no idea where one thought ends and the next begins. The tags aren’t decoration; they’re how you tell it.</p>
</section>

<section id="breaks">
<h2>5. Line breaks: <code>&lt;br /&gt;</code></h2>
<p>Here’s something that surprises everyone once. In the code, <strong>pressing Enter does nothing.</strong> You can put every line of an address on its own line in the file, and the browser will run them all together on one line anyway. <strong>Extra spaces do nothing either</strong> - ten spaces between two words show up as one. The browser squashes any run of spaces and new lines down to a single space. All that neat indentation in the AI’s code? That’s for <em>you</em>, so you can see what’s inside what. The browser politely ignores it.</p>
<p>When you want a line to end <em>inside</em> a paragraph - the lines of an address, a poem, a recipe’s ingredient list - you say so with <code>&lt;br /&gt;</code>. It means <em>break the line here</em>.</p>
<p>Look at it closely: <code>&lt;br /&gt;</code>. It has no closing tag, because there’s nothing to put inside a line break. Instead the slash goes <em>at the end</em>, inside the same tag. That slash is the signal that this tag is complete on its own. You’ll see <code>&lt;br&gt;</code> without the slash out in the world, and browsers accept it; in this course we write <code>&lt;br /&gt;</code>, because the slash reminds you that nothing goes inside, and you’ll meet other tags that work the same way soon.</p>
<p>In the demo, the address below is broken. Two lines have their <code>&lt;br /&gt;</code> and two don’t. <strong>Add the missing ones.</strong></p>

<div class="demo" data-file="address.html">
<textarea>&lt;!DOCTYPE html&gt;
&lt;html&gt;
  &lt;body&gt;
    &lt;h1&gt;Where to find us&lt;/h1&gt;
    &lt;p&gt;
      Finger Lakes Community College&lt;br /&gt;
      3325 Marvin Sands Drive
      Canandaigua, NY 14424&lt;br /&gt;
      United States
    &lt;/p&gt;
  &lt;/body&gt;
&lt;/html&gt;</textarea>
</div>

<h3>Two or three in a row</h3>
<p>Sometimes you want a gap, not just a new line - a blank line between the stanzas of a poem, or a little air before a signature. Two <code>&lt;br /&gt;</code>s in a row make one blank line; three make a bigger gap. That’s fine and normal.</p>
<p>But if you find yourself using <code>&lt;br /&gt;&lt;br /&gt;</code> to separate <em>paragraphs</em>, stop: that’s what <code>&lt;p&gt;</code> is for. The rule of thumb: <strong><code>&lt;p&gt;</code> for a new thought, <code>&lt;br /&gt;</code> for a new line inside the same thought.</strong></p>
<p class="aside">This is also why you never have to worry about getting the spacing “right” when you paste code from the AI. If it works, it works. The only thing spacing can affect is how easy the file is to read - so keep it tidy for your own sake, not the browser’s.</p>

<div class="demo" data-file="poem.html">
<textarea>&lt;!DOCTYPE html&gt;
&lt;html&gt;
  &lt;body&gt;
    &lt;p&gt;
      Roses are red,&lt;br /&gt;
      violets are blue.&lt;br /&gt;
      &lt;br /&gt;
      A break makes a line,&lt;br /&gt;
      and two make a gap too.
    &lt;/p&gt;
  &lt;/body&gt;
&lt;/html&gt;</textarea>
</div>

<section id="comments">
<h2>6. Comments: notes to humans</h2>
<p>Code files can contain notes that the browser skips entirely. They’re called <strong>comments</strong>, and they’re for people - a reminder of what a section does, a note from the AI explaining a block, a line you want to keep but not use right now.</p>
<p>In HTML a comment starts with <code>&lt;!--</code> and ends with <code>--&gt;</code>. In JavaScript, inside <code>&lt;script&gt;</code>, a comment is a line that starts with <code>//</code>. You saw those in the six-landmarks demo above.</p>
<p>Here’s why this matters more for you than for most people learning to code: <strong>the AI is going to write your code, and it writes a lot of comments.</strong> The specification you paste into every prompt asks it to explain every block in plain language, so when you open a file the AI built, nearly every chunk has a sentence above it saying what that chunk does. Those comments aren’t for the browser and they aren’t really for the AI. They’re for <em>you</em> - they’re how you’ll find your way around code you didn’t write, and they’re the first place to look when you want to change something.</p>
<p>In the demo, one line is commented out. <strong>Remove the <code>&lt;!--</code> and <code>--&gt;</code></strong> around it and watch it appear.</p>

<div class="demo" data-file="comments.html">
<textarea>&lt;!DOCTYPE html&gt;
&lt;html&gt;
  &lt;body&gt;
    &lt;!-- This is a comment. The browser ignores it completely. --&gt;
    &lt;h1&gt;Comments&lt;/h1&gt;
    &lt;p&gt;You can see this paragraph.&lt;/p&gt;
    &lt;!-- &lt;p&gt;You cannot see this one, because it is commented out.&lt;/p&gt; --&gt;
  &lt;/body&gt;
&lt;/html&gt;</textarea>
</div>

<section id="wrong">
<h2>7. Where it goes wrong</h2>
<p>Four things account for nearly every broken first page. You’ve now seen the shape of each one.</p>
<ul>
  <li><strong>A missing closing tag.</strong> Everything after it inherits the tag - a whole page turns into one giant heading. You saw this in section 2. Fix: find the tag that never closed.</li>
  <li><strong>A slash in the wrong place.</strong> <code>&lt;h1/&gt;</code> is not a heading and <code>&lt;/br&gt;</code> is not a line break. The slash goes at the <em>front</em> of a closing tag (<code>&lt;/h1&gt;</code>) and at the <em>end</em> of a self-closing one (<code>&lt;br /&gt;</code>).</li>
  <li><strong>The file isn’t really <code>.html</code>.</strong> If the browser shows you the tags as text, angle brackets and all, the file was saved as <code>.txt</code>. That’s the setup lab’s whole reason for existing.</li>
  <li><strong>It went through a word processor.</strong> Word and Google Docs add invisible formatting to text. Code that passed through one may look right and not work. Always copy from the AI straight into TXTEDTR.</li>
</ul>
</section>

      // so a returning student lands where they left off.
      // ---------------------------------------------------------------
      steps.forEach(renderStep);
      renderProgress();
      const firstOpen = steps.find(function (s) { return !done.includes(Number(s.dataset.step)); }) || steps[0];

    })();

    /* ====================================================================
       Vibe Coding - vocabulary pop-ups
       Inlined by the build into every lab and reading, after lab.js.

       The build also inlines a VOCAB object (from shared/vocabulary.html):

         VOCAB = {
           "tag": { title: "Tag", match: ["tag", "tags"], html: "<p>...</p>" },
           ...
         }

       What this script does:
         1. Walks the text of the page and, the FIRST time a vocabulary term
            appears in each step (or each section, on a reading), wraps that
            word in a small button. Later mentions in the same step are left
            alone, so a page is not covered in links.
         2. Clicking the button opens a small pop-up (a native <dialog>) with
            the term's definition and a link to the full vocabulary page.

       It never touches code samples in <pre>, the demo <textarea>s, links,
       other buttons, headings, or the pretend-browser chrome. Inline <code>
       IS allowed, on purpose: that is where "<title>" appears in a sentence.
       ==================================================================== */
    (function () {
      'use strict';
      if (typeof VOCAB !== 'object' || !VOCAB) return;
      const dialog = document.getElementById('vocab-dialog');
      if (!dialog) return;

      // ---------------------------------------------------------------
      // 1. ONE REGULAR EXPRESSION FOR EVERY SPELLING OF EVERY TERM
      // Longest spellings first, so "opening tag" wins over "tag".
      // ---------------------------------------------------------------
      const spellings = [];             // [{ text, id }]
      Object.keys(VOCAB).forEach(function (id) {
        (VOCAB[id].match || []).forEach(function (text) {
          if (text.trim()) spellings.push({ text: text.trim(), id: id });
        });
      });
      spellings.sort(function (a, b) { return b.text.length - a.text.length; });
      const byLower = {};
      spellings.forEach(function (s) { byLower[s.text.toLowerCase()] = s.id; });

      function escapeRegex(text) { return text.replace(/[.*+?^${}()|[\]\\]/g, '\\$&'); }
      const pattern = new RegExp(spellings.map(function (s) { return escapeRegex(s.text); }).join('|'), 'gi');

      // A match only counts if it is a whole word: no letter or digit directly
      // before it (when it starts with one) or after it (when it ends with one).
      // "tag" must not light up inside "tags" or "stage".
      // Dots, hyphens, slashes and underscores count as glue too, so "html" does
      // not light up inside the file name "qr-code.html".
      const GLUE = /[\w.\-\/_]/;
      function isWholeWord(text, start, end) {
        const first = text[start], last = text[end - 1];
        const before = text[start - 1] || ' ', after = text[end] || ' ';
        if (/\w/.test(first) && GLUE.test(before)) return false;
        if (/\w/.test(last) && GLUE.test(after)) return false;
        return true;
      }

      // ---------------------------------------------------------------
      // 2. WHERE NOT TO LOOK
      // ---------------------------------------------------------------
      const SKIP = 'pre, textarea, svg, a, button, label, input, select, script, style, h1, h2, dialog, .fake-chrome, .contents, .ribbon, .term-link, .tools-note, .submit-card';

      function skippable(node) {
        for (let el = node.parentElement; el; el = el.parentElement) {
          if (el.matches(SKIP)) return true;
        }
        return false;
      }

      // ---------------------------------------------------------------
      // 3. LINK THE FIRST MENTION OF EACH TERM IN EACH BLOCK
      // A "block" is a step body on a lab, or a section on a reading.
      // ---------------------------------------------------------------
      const main = document.getElementById('main');
      if (!main) return;
      let blocks = Array.from(main.querySelectorAll('.step-body, :scope > section'));
      if (!blocks.length) blocks = [main];

      blocks.forEach(function (block) {
        const seen = new Set();
        const walker = document.createTreeWalker(block, NodeFilter.SHOW_TEXT);
        const textNodes = [];
        let node;
        while ((node = walker.nextNode())) {
          if (node.nodeValue.trim() && !skippable(node)) textNodes.push(node);
        }
        textNodes.forEach(function (textNode) { linkTerms(textNode, seen); });
      });

      function linkTerms(textNode, seen) {
        const text = textNode.nodeValue;
        pattern.lastIndex = 0;
        let match, last = 0;
        const pieces = [];
        while ((match = pattern.exec(text))) {
          const start = match.index, end = start + match[0].length;
          const id = byLower[match[0].toLowerCase()];
          if (!id || seen.has(id) || !isWholeWord(text, start, end)) continue;
          seen.add(id);
          pieces.push(document.createTextNode(text.slice(last, start)));
          const button = document.createElement('button');
          button.type = 'button';
          button.className = 'term-link';
          button.dataset.term = id;
          button.textContent = match[0];
          button.setAttribute('aria-label', match[0] + ' - show definition');
          pieces.push(button);
          last = end;
        }
        if (!pieces.length) return;
        pieces.push(document.createTextNode(text.slice(last)));
        const parent = textNode.parentNode;
        pieces.forEach(function (piece) { parent.insertBefore(piece, textNode); });
        parent.removeChild(textNode);
      }

      // ---------------------------------------------------------------
      // 4. THE POP-UP
      // A native <dialog>: Escape closes it, focus stays inside it, and the
      // page behind is dimmed. When it closes, focus goes back to the word
      // that opened it.
      // ---------------------------------------------------------------
      const titleEl = dialog.querySelector('#vocab-title');
      const bodyEl  = dialog.querySelector('#vocab-body');
      const moreEl  = dialog.querySelector('#vocab-more');
      let opener = null;

      function open(id, button) {
        const entry = VOCAB[id];
        if (!entry) return;
        opener = button;
        titleEl.innerHTML = entry.title;
        // The definition HTML comes from shared/vocabulary.html, written by the
        // course author and inlined at build time - not from anything a visitor
        // typed - so putting it in with innerHTML is safe here.
        bodyEl.innerHTML = entry.html;
        if (moreEl) moreEl.hash = '#' + id;
        if (typeof dialog.showModal === 'function') { dialog.showModal(); } else { dialog.setAttribute('open', ''); }
      }

      document.addEventListener('click', function (e) {
        const button = e.target.closest('.term-link');
        if (button) { e.preventDefault(); open(button.dataset.term, button); }
      });

      dialog.querySelector('#vocab-close').addEventListener('click', function () { dialog.close(); });
      // Clicking the dimmed backdrop (outside the pop-up's box) closes it too.
      dialog.addEventListener('click', function (e) {
        const box = dialog.getBoundingClientRect();
        const outside = e.clientX < box.left || e.clientX > box.right || e.clientY < box.top || e.clientY > box.bottom;
        if (outside) dialog.close();
      });
      dialog.addEventListener('close', function () { if (opener) { opener.focus(); opener = null; } });
    })();
  </script>

       Inlined by the build into every reading page, after lab.js (which

    (function () {

      // Turn every .demo block on the page into a live widget.
      document.querySelectorAll('.demo').forEach(buildDemo);

      function buildDemo(demo, index) {

        if (!textarea) return;

        // Tall enough to show the whole starting code without scrolling (up to a limit).
        textarea.rows = Math.min(original.split('\n').length + 1, 26);
        textarea.setAttribute('spellcheck', 'false');
        textarea.setAttribute('autocapitalize', 'off');
        textarea.setAttribute('autocomplete', 'off');

        const codePane = document.createElement('div');
        codePane.className = 'demo-code';
        codePane.innerHTML =
          '<div class="demo-bar">' +
          '  <label for="' + id + '-code">Code <span class="demo-hint">- edit me</span></label>' +
          '  <span class="demo-buttons">' +
          (demo.dataset.squish === 'yes'
            ? '<button type="button" class="btn quiet demo-squish">Squish</button>' +
              '<button type="button" class="btn quiet demo-spread">Spread out</button>'
            : '') +
          '  <button type="button" class="btn quiet demo-reset">Reset</button>' +
          '  </span>' +
          '</div>';
        codePane.appendChild(textarea);

        // The pretend browser. Everything here is decoration except the iframe,
        // which really does render the code.
        const browser = document.createElement('div');
        browser.className = 'demo-browser';
        browser.innerHTML =
          '<div class="fake-chrome" aria-hidden="true">' +
          '  <div class="fake-tabs">' +
          '    <span class="fake-dots"><i></i><i></i><i></i></span>' +
          '    <span class="fake-tab"><span class="fake-favicon"></span><span class="fake-title"></span></span>' +
          '  </div>' +
          '  <div class="fake-address"><span class="fake-nav">‹ › ↻</span><span class="fake-url"></span></div>' +
          '</div>' +
          '<iframe class="demo-frame" title="Rendered page for this demo" sandbox="allow-scripts"></iframe>';

        demo.innerHTML = '';
        demo.append(codePane, browser);

        const frame    = browser.querySelector('.demo-frame');
        const tabTitle = browser.querySelector('.fake-title');
        const urlBox   = browser.querySelector('.fake-url');
        urlBox.textContent = 'file:///Desktop/vibe-coding/' + fileName;

        // ---- Rendering ----
        // The tab shows whatever is between <title> and </title>. When a page has
        // no title, real browsers show the file name instead - so do we. That is
        // a small lesson in itself: the tab is never blank, it just falls back.
        function render() {
          const code = textarea.value;
          frame.srcdoc = code;
          const match = code.match(/<title>([\s\S]*?)<\/title>/i);
          const title = match ? match[1].replace(/\s+/g, ' ').trim() : '';
          tabTitle.textContent = title || fileName;
        }

        // Re-render a moment after the student stops typing, not on every key,
        // so a slow machine does not stutter.
        let timer = null;
        textarea.addEventListener('input', function () {
          clearTimeout(timer);
          timer = setTimeout(render, 150);
        });

        // Tab key inside the code box inserts two spaces instead of moving focus,
        // which is what a code editor does. Escape then Tab still moves focus, so
        // keyboard users are never trapped - and we say so in the label's title.
        let escaped = false;
        textarea.title = 'Tab inserts spaces here. Press Escape, then Tab, to move on.';
        textarea.addEventListener('keydown', function (e) {
          if (e.key === 'Escape') { escaped = true; return; }
          if (e.key === 'Tab' && !escaped) {
            e.preventDefault();
            const start = textarea.selectionStart, end = textarea.selectionEnd;
            textarea.setRangeText('  ', start, end, 'end');
            textarea.dispatchEvent(new Event('input'));
          }
          escaped = false;
        });

        // ---- Buttons ----
        codePane.querySelector('.demo-reset').addEventListener('click', function () {
          textarea.value = original;
          render();
          textarea.focus();
        });

        const squish = codePane.querySelector('.demo-squish');
        if (squish) {
          // Squish: every run of spaces, tabs and newlines becomes one space.
          // The browser treats them the same, so the render does not change.
          squish.addEventListener('click', function () {
            textarea.value = textarea.value.replace(/\s+/g, ' ').trim();
            render();
          });
          // Spread out: back to the nicely indented original.
          codePane.querySelector('.demo-spread').addEventListener('click', function () {
            textarea.value = original;
            render();
          });
        }

        render();
      }
    })();
  </script>
